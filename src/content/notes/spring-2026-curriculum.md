2026년 봄학기에는 작은 행렬 곱셈기에서 시작해 연산 셀을 연결하고, 결과를 저장하고, 메모리에서 입력을 읽는 구조로 확장했습니다. 탁효빈이 학습자료와 과제를 준비했고, 멤버들은 같은 과제를 각자 구현해 코드와 테스트벤치를 제출했습니다.

과제 번호는 공지에 붙인 주차 번호입니다. 3주차와 4주차에는 과제 3(제어기와 결과 수확) 하나를 이어서 다뤘기 때문에 과제 4는 따로 없습니다.

## 과제 일정

| 과제 | 날짜 | 내용 |
|---|---|---|
| 과제 1 | 4월 5~10일 제출 | 2×2 행렬곱, 연산 모듈 분리, 테스트벤치 |
| 과제 2 | 4월 22일 공지, 5월 7~8일 제출 | 4×4 weight-stationary 어레이, PE 연결과 입력 시점 제어 |
| 과제 3 | 5월 13일 공지, 5월 14~16일 제출 | 8비트 확장, 결과 수확, 지연 시간 분석 |
| 과제 5 | 5월 20일 공지, 5월 22일 제출 | 입력·가중치 BRAM과 주소 생성 |
| 과제 6 (선택) | 5월 25일 공지 | 출력 BRAM, 결과 쓰기 제어, 쓰기 완료 후 읽기 |

## 과제 1: 같은 행렬곱을 다르게 만들기

첫 단계는 4비트 입력으로 2×2 행렬 A와 B를 곱해 C를 구하는 회로였습니다. 과제는 MAC PE를 모듈로 만들고 상위 모듈에서 연결하도록 했습니다. 제출된 코드에는 서로 다른 접근이 보입니다.

- 한 출력 원소에 필요한 두 곱을 함께 계산하고 더하는 방식
- 곱셈 결과를 여러 클럭에 걸쳐 누적하는 방식
- 입력을 엇갈려 넣고, 이웃 PE로 데이터를 전달하면서 각 PE에 결과를 누적하는 방식 (output-stationary)

같은 행렬곱이라도 연산기를 얼마나 두는지, 중간값을 어디에 저장하는지, 언제 입력을 받는지에 따라 회로가 달라집니다. 이 차이는 [같은 2×2 행렬곱을 서로 다르게 구현하기](/notes/matrix-multiplier-designs/)에서 비교합니다.

## 과제 2: 4×4 weight-stationary 어레이

4월 22일 공지에서는 입력과 가중치가 4비트인 4×4 행렬곱을 요구했습니다. PE 16개를 연결하고, 가중치를 PE 안에 미리 저장하며, 입력은 오른쪽으로, 부분합은 아래로 전달하는 구조입니다.

제어기는 IDLE, LOAD_WEIGHT, CALC, DONE을 구분하도록 했습니다. 제출물에는 `generate`를 이용한 연결, 가중치 로드·연산 제어, 행마다 입력 시점을 엇갈리게 만드는 로직이 있습니다.

일부 제출물은 클럭마다 할 일을 FSM 상태로 나눴고, 다른 제출물은 카운터와 배열 인덱스로 입력 순서를 만들었습니다. 전체 데이터 흐름은 [weight-stationary 데이터 흐름 노트](/notes/weight-stationary-dataflow/)에서 볼 수 있습니다.

## 과제 3: 계산 결과를 저장하기

5월 13일 공지의 목표는 8비트 입력으로 확장하고, 결과가 지나가는 시점을 계산해 원소 16개를 보존하는 것이었습니다. 첫 결과와 마지막 결과가 나오는 시점은 파형으로 설명하도록 했습니다.

5월 14~16일에는 더 넓은 결과 폭을 다루는 코드와, 시간차를 두고 나오는 출력을 4×4 결과 행렬에 저장하는 코드가 제출되었습니다. 결과 저장을 별도 수확 모듈로 나눈 제출물도 있습니다.

어레이 맨 아래의 출력은 매 클럭 바뀔 수 있어 각 값이 유효한 시점에 저장해야 합니다. 부분합과 결과의 폭은 입력 범위까지 고려해야 합니다. 부호 없는 8비트 값 네 쌍을 곱해 더하는 경우 전체 범위를 표현하려면 18비트가 필요합니다.

출력의 도착 순서와 저장 시점은 [Systolic Array의 결과를 언제 저장해야 할까?](/notes/systolic-result-harvesting/)에 정리했습니다.

## 과제 5: 메모리에서 입력 읽기

5월 20일 공지는 Vivado Block Memory Generator로 입력용 A_Buffer와 가중치용 W_Buffer를 각각 8비트 폭·깊이 16으로 구성하도록 했습니다. 이 과제에서는 한 클럭의 읽기 지연에 맞춰 주소와 연산 제어를 정렬하는 것을 요구했습니다.

5월 22일 제출물에는 메모리, 읽기 주소를 만드는 로직, 읽어 온 값을 담는 버퍼, 연산기를 묶는 상위 모듈이 있습니다. 메모리 초기값을 담는 `.coe` 파일도 제출되었습니다.

실제 읽기 지연은 사용하는 메모리 설정과 맞춰야 합니다. 자세한 내용은 [테스트벤치 입력에서 BRAM 입력으로 바꾸기](/notes/bram-fed-systolic-array/)에서 설명합니다.

## 과제 6: 출력 버퍼와 결과 쓰기 제어 · 선택 과제

5월 25일에는 결과 행렬을 C_Buffer에 순서대로 기록하는 선택 과제를 공지했습니다. 공지의 구성은 출력 BRAM, 행 우선 순서의 쓰기 주소 생성, 쓰기 완료 신호, 완료 후 호스트 읽기입니다.

출력 버퍼 폭은 저장할 결과의 범위와 일치해야 합니다. 공지에서 정한 16비트 버퍼를 사용할 경우에도 입력 범위나 잘림 정책을 확인해야 합니다. 또한 결과 수확에 필요한 클럭 수는 실제 출력 일정에 맞춰야 합니다.

필수가 아닌 선택 과제였고, 입력 메모리에서 출력 메모리까지 데이터 경로를 닫는 것이 목표였습니다.
