2026년 봄학기에는 작은 행렬 곱셈기에서 시작해 연산 셀을 연결하고, 결과를 저장하고, 메모리에서 입력을 읽는 구조로 확장했습니다. 멤버들은 같은 과제를 각자 구현해 코드와 테스트벤치를 제출했습니다.

이 글은 1·2·3주차 묶음 채널, 4주차 채널, 5주차 채널의 제출 기록을 바탕으로 정리했습니다. 2·3주차는 묶어서 소개하며, 제출물마다 비트 폭과 제어기를 확장한 시점은 다릅니다.

## 제출 기록으로 보는 진행 과정

| 단계 | 제출일 | 확인되는 작업 |
|---|---|---|
| 1주차 | 4월 5~10일 | 2×2 행렬 곱셈기, 연산 모듈 분리, 테스트벤치 |
| 2·3주차 | 5월 7~8일 | 4×4 weight-stationary 어레이, PE 연결, 가중치 로드와 입력 시점 제어 |
| 4주차 | 5월 14~16일 | 8비트 입력을 다루는 확장, 출력 시점에 맞춘 결과 행렬 저장 |
| 5주차 | 5월 22일 | 입력·가중치 BRAM, 읽기 주소 생성, 버퍼와 연산기 연결 |

## 1주차: 같은 행렬곱을 다르게 만들기

첫 단계는 2×2 행렬 A와 B를 곱해 C를 구하는 회로였습니다. 제출된 코드에는 서로 다른 접근이 보입니다.

- 한 출력 원소에 필요한 두 곱을 함께 계산하고 더하는 방식
- 곱셈 결과를 여러 클럭에 걸쳐 누적하는 방식
- 입력을 엇갈려 넣고, 이웃 PE로 데이터를 전달하면서 각 PE에 결과를 누적하는 방식

같은 행렬곱이라도 연산기를 얼마나 두는지, 중간값을 어디에 저장하는지, 언제 입력을 받는지에 따라 회로가 달라집니다. 이름이 같은 MAC PE여도 내부 구조는 같지 않았습니다.

이 차이는 [같은 2×2 행렬곱을 서로 다르게 구현하기](/notes/matrix-multiplier-designs/)에서 비교합니다. 제출 코드의 구조를 설명하는 비교이며, 성능 순위를 매긴 결과는 아닙니다.

## 2·3주차: 4×4 weight-stationary 어레이

다음 단계에서는 PE 16개를 격자로 연결했습니다. 가중치는 PE 안에 저장하고, 입력은 오른쪽으로, 부분합은 아래로 전달합니다. 제출물에는 `generate`를 이용한 PE 연결과 가중치 로드·연산 단계를 나누는 제어기가 있습니다.

입력을 같은 순간에 모두 넣는 대신 행마다 시점을 어긋나게 만드는 로직도 등장합니다. 왼쪽에서 오는 입력과 위에서 오는 부분합이 같은 연산에 해당하도록 맞추기 위해서입니다.

일부 제출물은 클럭마다 할 일을 FSM 상태로 나눴고, 다른 제출물은 카운터와 배열 인덱스로 입력 순서를 만들었습니다. 전체 데이터 흐름은 [weight-stationary 데이터 흐름 노트](/notes/weight-stationary-dataflow/)에서 볼 수 있습니다.

## 4주차: 계산 결과를 저장하기

4주차 채널에는 8비트 입력과 더 넓은 결과 폭을 다루는 코드, 그리고 시간차를 두고 나오는 출력을 4×4 결과 행렬에 저장하는 코드가 제출되었습니다. 결과 저장을 별도 수확 모듈로 나눈 제출물도 있습니다.

어레이 맨 아래의 출력은 매 클럭 바뀔 수 있습니다. 연산이 끝날 때 마지막 값만 읽으면 앞서 나온 결과를 놓치므로, 각 값이 유효한 시점에 저장해야 합니다. 입력이 8비트가 되면 여러 곱을 더한 결과가 넘치지 않도록 부분합의 폭도 확인해야 합니다.

출력의 도착 순서와 저장 시점은 [Systolic Array의 결과를 언제 저장해야 할까?](/notes/systolic-result-harvesting/)에 정리했습니다.

## 5주차: 메모리에서 입력 읽기

5주차 제출물에서는 테스트벤치가 직접 넣던 행렬과 가중치를 BRAM에서 읽도록 연결했습니다. 입력용·가중치용 메모리, 읽기 주소를 만드는 로직, 읽어 온 값을 담는 버퍼, 연산기를 묶는 상위 모듈이 확인됩니다. 메모리 초기값을 담는 `.coe` 파일도 제출되었습니다.

메모리를 붙일 때는 주소뿐 아니라 데이터가 돌아오는 시점도 맞춰야 합니다. 주소를 낸 클럭과 해당 데이터를 버퍼에 저장하는 클럭을 구분하는 것이 핵심입니다. 자세한 내용은 [테스트벤치 입력에서 BRAM 입력으로 바꾸기](/notes/bram-fed-systolic-array/)에서 설명합니다.

## 기록의 범위

코드와 테스트벤치를 제출하며 2×2 행렬곱에서 결과 저장·메모리 연동까지 구조를 확장한 과정을 볼 수 있습니다. 개별 구현의 정답 일치와 보드 동작은 해당 코드 버전의 파형·로그·실행 결과를 근거로 확인해야 합니다.

프로젝트의 구조와 기존 결과는 [4×4 Systolic Array NPU](/projects/systolic-4x4/)에 모았습니다.
