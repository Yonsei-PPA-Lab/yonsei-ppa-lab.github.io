처음에는 테스트벤치가 행렬과 가중치를 연산기의 입력 포트에 직접 넣었습니다. 5주차 과제에서는 그 값을 BRAM에서 읽도록 확장한 코드가 제출되었습니다. 연산기가 필요한 데이터를 어떤 주소에서, 언제 가져올지도 회로가 맡게 된 것입니다.

## 제출물에 등장한 구성

| 구성 | 하는 일 |
|---|---|
| 입력·가중치 BRAM | 행렬 원소와 가중치를 저장 |
| 읽기 주소 생성 로직 | 메모리에서 읽을 위치를 순서대로 지정 |
| 읽기 버퍼 | 메모리에서 돌아온 값을 보관 |
| 입력 공급 로직 | 읽은 값을 PE의 입력 순서에 맞춰 전달 |
| 상위 모듈 | 메모리, 제어기, 어레이의 포트 연결 |

어떤 제출물은 BRAM과 어레이를 상위 모듈에서 직접 연결하고, 다른 제출물은 읽기 시퀀서와 입력 공급 모듈을 분리했습니다. 입력·가중치 메모리의 초기값을 담는 `.coe` 파일도 제출되었습니다.

## 주소를 보낸 순간과 데이터를 읽는 순간

동기식 BRAM은 주소를 바꾼 즉시 조합 논리처럼 데이터를 내주는 인터페이스가 아닙니다. 읽기 지연과 출력 레지스터 설정을 확인해야 합니다.

```text
읽기 주소 전달
    ↓ 메모리 설정에 따른 읽기 지연
해당 주소의 데이터 수신
    ↓
버퍼의 올바른 위치에 저장
    ↓
가중치 로드 / 연산 입력 공급
```

주소 카운터의 현재 값이 곧 지금 돌아온 데이터의 주소라고 가정하면 한 원소씩 밀려 저장될 수 있습니다. 데이터가 돌아오는 시점에 맞춰 저장 인덱스나 유효 신호를 함께 관리해야 합니다.

5주차 제출 코드 일부에서는 읽기 카운터의 이전 위치를 이용해 버퍼의 행·열을 정합니다. 이 식이 맞는지는 카운터가 증가하는 클럭과 실제 메모리의 읽기 지연을 함께 확인해야 합니다. 모든 BRAM 구성에 같은 식을 그대로 적용할 수는 없습니다.

## 메모리 순서와 어레이 입력 순서는 다르다

메모리는 원소를 주소 순서로 읽어도, 어레이에는 입력을 행마다 엇갈려 넣어야 할 수 있습니다. 가중치를 적재하는 순서 역시 각 PE에 도착해야 하는 위치와 맞아야 합니다.

따라서 메모리의 저장 순서, 버퍼의 행·열 인덱스, PE에 공급하는 순서를 따로 정하고 연결해야 합니다. 0이나 같은 값만 가득한 행렬보다 위치마다 다른 값을 가진 작은 예제가 주소·인덱스 오류를 찾기 좋습니다.

## 연산까지 이어지는 제어

1. 시작 요청을 받으면 읽기 상태와 주소를 초기화합니다.
2. 필요한 입력·가중치를 읽고 마지막 응답까지 받습니다.
3. 해당 구현의 방식에 맞춰 가중치를 PE에 적재합니다.
4. 입력 공급과 연산을 진행합니다.
5. 유효한 출력을 저장하고 결과가 완성되었음을 알립니다.

위 순서는 버퍼를 채운 뒤 계산하는 구조를 설명한 것입니다. 읽기와 계산을 겹치는 구조라면 데이터 유효 여부와 공급이 멈췄을 때의 동작을 추가로 정의해야 합니다.

## 검증할 때 확인할 것

읽기 주소와 데이터의 대응, 첫·마지막 원소, 리셋 후 재시작, 연속된 두 행렬의 결과를 확인합니다. 결과 저장 시점은 [수확 로직 노트](/notes/systolic-result-harvesting/)와 함께 보면 좋습니다.
