## 개요

PPA Lab 멤버 세 명이 팀 **회로 YAHO~** 로 2026 전국 대학생 AI 반도체 회로 설계 경진대회에 참가해 만든 2차 과제 설계입니다. 2차 결과물을 2026년 10월 30일에 제출했습니다. 같은 대회에 나간 [반도체 YAHO~ 팀의 2차 설계](/projects/event-world-mapper/)와 과제는 같고 접근은 다릅니다.

과제는 고정된 위치에서 방향을 바꾸는 이벤트 센서의 출력을 월드 메모리의 올바른 위치에 쌓는 것입니다. 센서가 회전해도 같은 방향에서 온 정보는 같은 월드 위치에 누적되어야 합니다.

제출한 회로 `wm_top`은 240×180 입력을 1024×192 크기의 **원통형 월드**에 매핑합니다. 월드의 가로 1024열이 수평 360도에 해당하므로, 센서의 좌우 회전(pan)은 월드에서 열 방향 이동이 됩니다.

## 구조

```text
SEG · POSE · FRAME 패킷
        ↓
세그먼트 스캐너 (1 px/cycle)
        ↓
좌표 변환 (LUT, 곱셈 1회, 덧셈 2회)
        ↓
쓰기 병합 버퍼 (4 엔트리)
        ↓
RMW 엔진 (읽기 1회 + 쓰기 1회)
        ↓
월드 SRAM (1024×192 셀 × 4비트)
```

- **패킷 입력**: 이벤트(SEG), 자세(POSE), 프레임 경계(FRAME)를 패킷으로 받습니다. 자세가 바뀌기 전에 들어온 이벤트에는 이전 자세를 적용하도록 순서를 지킵니다. 960×720 센서 출력을 240×180으로 줄이는 4×4 binning과 패킷 생성은 Python 전처리가 맡습니다.
- **자세 입력 선택**: 외부에서 pan과 tilt를 받거나, 칩 안의 pan 추정기를 쓸 수 있습니다. 추정기는 열 히스토그램 두 개를 ±16열 범위에서 비교해 pan 속도를 구하고 적분합니다.
- **월드 메모리**: 셀 하나는 4비트 포화 카운터입니다. 4×4셀을 64비트 워드 하나로 묶어 12,288워드, 96 KiB가 됩니다.

## LUT 좌표 변환

원통형 좌표로 바꾸는 식에는 삼각함수와 나눗셈이 들어갑니다. 그런데 센서 열 x에만 의존하는 항은 미리 계산해 둘 수 있습니다.

```text
world_col = pan + COL[x]  mod 1024
world_row ≈ 96 + tilt
            + y_centered × G[x]
```

`COL`과 `G`를 ROM에 넣어 두면 런타임에는 조회, 곱셈 한 번, 덧셈 두 번만 남습니다. 같은 매핑을 CORDIC과 나눗셈기로 만든 유닛과 비교했습니다.

| 좌표 변환 유닛 | 로직 면적 (µm²) | 전력 (mW) |
|---|---|---|
| CORDIC + 나눗셈기 | 35,123 | 1.341 |
| LUT | 1,662 | 0.097 |

면적은 21배, 전력은 14배 작습니다. 다만 이것은 좌표 변환 유닛만의 비교이고 칩 전체의 감소율은 아닙니다.

## 쓰기 병합

이벤트마다 메모리를 읽고 고쳐 쓰면 접근 횟수가 이벤트 수만큼 생깁니다. 이웃한 이벤트는 같은 워드에 떨어지는 일이 많으므로, 4개 엔트리 버퍼에 워드별 증가량을 모아 두었다가 버퍼가 차거나 프레임이 끝날 때 한 번에 반영합니다.

```text
cell_new = min(15, cell_old + hits)
```

음수가 없는 포화 덧셈은 묶어서 더해도 결과가 같습니다. 그래서 쓰기 순서를 바꿔도 최종 월드 메모리는 이벤트별로 쓴 것과 동일합니다.

| 실제 데이터 | SRAM 쓰기 횟수 | 감소 |
|---|---|---|
| Rod, 1,452프레임 | 7,568,537 → 983,853 | 7.7배 |
| Turntable, 1,620프레임 | 7,788,945 → 1,119,232 | 7.0배 |

위 값은 외부 자세를 사용한 Python 모델로 전체 구간을 집계한 것입니다. 병합 버퍼만큼 로직은 커집니다. 전체 매퍼의 합성 면적은 52,696 µm²에서 56,706 µm²로, 전력은 1.607 mW에서 1.757 mW로 늘었습니다. 대신 Rod 전체 구간의 에너지는 메모리 접근까지 합쳐 990.9 µJ에서 250.5 µJ로 약 4배 줄어드는 것으로 추정했습니다.

## 합성과 배치·배선

Cadence GPDK045 공정에서 Genus와 Innovus로 합성과 배치·배선을 했습니다. 목표 주파수는 100 MHz입니다.

| 항목 | 값 |
|---|---|
| 클럭 주기 | 10.0 ns (100 MHz) |
| 전체 매퍼 로직 면적 (합성) | 56,706 µm² |
| Setup / Hold slack | +0.074 ns / +0.002 ns |
| 타이밍 위반 경로 | 0 |
| DRC / antenna | 0 / 0 |

## 검증

회로와 같은 정수 연산을 하는 Python 기준 모델을 만들고, 시뮬레이션이 끝난 뒤 월드 메모리 전체와 쓰기 횟수를 대조했습니다.

| 단계 | 입력 | 결과 |
|---|---|---|
| RTL, 외부 자세 | 실제 데이터 300프레임, 입력 stall 20% | 쓰기 204,479회, 워드 불일치 0 |
| RTL, 내부 추정기 | 실제 데이터 300프레임, 입력 stall 20% | 쓰기 195,677회, 워드 불일치 0 |
| 게이트 + SDF | 합성 입력 60프레임, 외부 자세 | 쓰기 9,250회, 워드 불일치 0 |

내부 추정기는 처음 16프레임 동안 매핑을 보류하기 때문에 두 경로의 쓰기 횟수는 직접 비교할 수 없습니다. 게이트 시뮬레이션에서 경로 지연은 전부 적용되었고, 타이밍 검사는 71%만 적용되어 reset 관련 검사는 보완이 필요합니다.

## 범위와 남은 과제

- 합성과 배치·배선 대상은 패킷 입력 이후의 매퍼 로직입니다. 월드 SRAM은 실제 매크로 대신 동작 모델을 썼고, SRAM의 면적과 에너지는 추정값입니다.
- 지금 모델은 pan 중심입니다. tilt는 행 오프셋으로 근사했고, roll 회전과 센서 이동은 다루지 않습니다. roll이 섞인 Turntable 데이터에서는 맵 품질에 한계가 있습니다.
- 내부 pan 추정기는 초기 구간의 응답과 긴 구간에서의 드리프트를 더 확인해야 합니다.
- SRAM 매크로와 클럭 제어를 합친 전체 칩 구현이 다음 단계입니다.
